# Puntillo

Веб-тренажёр чтения нот с листа. Vue 3 + TypeScript.

Полное техническое задание: `docs/spec.md`. Читать перед любой работой. При расхождении между этим файлом и ТЗ приоритет у ТЗ.

## Процесс

Работа ведётся по фичам и срезам. Определения и правила — раздел 15 ТЗ.

1. Фича начинается с файла критериев приёмки в `docs/features/<имя>.md` по шаблону `docs/features/TEMPLATE.md`. Файл со статусом `утверждено` — единственное основание для начала работы. Без него код не пишется.
2. Фича нарезается на срезы. Каждый срез — вертикальный, проходит все слои, заканчивается демонстрируемым результатом. Список срезов записывается в файл фичи.
3. Срез реализуется по TDD в двух ролях. Роль A пишет падающие тесты по критериям среза и не касается продуктового кода. Роль B делает тесты зелёными минимальным кодом, затем рефакторит, и не касается тестов. Некорректный тест возвращается роли A с описанием проблемы, а не исправляется на месте.
4. Внутри среза порядок слоёв: домен → приложение → инфраструктура → интерфейс. К следующему слою переходить только при зелёных тестах предыдущего.
5. Срез готов при выполнении всех пунктов раздела 15.7 ТЗ. После этого он вливается в основную ветку.

## Эскалация

Если решение влияет на видимое пользователю поведение и не покрыто критериями фичи — остановиться и спросить. Не выбирать поведение по умолчанию молча. Не достраивать спецификацию самостоятельно.

## Архитектура

Четыре слоя, зависимости только внутрь: `presentation → application → domain ← infrastructure`.

- `domain` не импортирует Vue, браузерные API и сторонние библиотеки.
- VexFlow вызывается только внутри компонента-адаптера нотоносца.
- Хранилище, звук, устройства ввода, источник случайности — за интерфейсами, инжектируются.
- Каталоги организуются по функциональным модулям, не по типам файлов.

## Библиотеки

Не писать своё там, где есть зрелое готовое. Список утверждённых зависимостей — раздел 14 ТЗ. Добавление новой зависимости обосновывается по критериям раздела 15.6 и фиксируется в файле фичи.

## Тесты

- Vitest для модульных и компонентных, Playwright для сквозных.
- Домен покрывается полностью.
- Компонентные тесты проверяют поведение пользователя, не внутреннее состояние.
- Пропуск или отключение теста без заведённой задачи запрещён.
- Тесты обновляются вместе с кодом в том же коммите.

## Стиль

- TypeScript strict. `any` не используется.
- Composition API, `<script setup>`.
- ESLint и Prettier обязательны, запускаются хуком перед коммитом.
- Имена типов и модулей — из раздела 2 ТЗ: `Pitch`, `Duration`, `Note`, `Question`, `Answer`, `Grade`, `Preset`, `Session`, `Slice`, `Feature`.

## Команды

Node.js версии из `.nvmrc`. Если системная версия ниже — `nvm use`.

| Команда                 | Назначение                                       |
| ----------------------- | ------------------------------------------------ |
| `npm run dev`           | Дев-сервер                                       |
| `npm run build`         | Сборка с проверкой типов                         |
| `npm run type-check`    | Проверка типов                                   |
| `npm run lint`          | Линтеры с автоисправлением                       |
| `npm run lint:check`    | Линтеры без изменений файлов                     |
| `npm run format`        | Форматирование                                   |
| `npm run format:check`  | Проверка форматирования                          |
| `npm run test:unit`     | Модульные и компонентные тесты, режим наблюдения |
| `npm run test:unit:run` | То же однократно                                 |
| `npm run test:coverage` | Тесты с покрытием                                |
| `npm run test:e2e`      | Сквозные тесты                                   |
| `npm test`              | Полная проверка перед вливанием среза            |

Границы слоёв проверяются правилом `no-restricted-imports` в `eslint.config.ts`.
Порог покрытия домена 100% задан в `vitest.config.ts`.
Хук перед коммитом — `.husky/pre-commit`: `lint-staged` и проверка типов.
